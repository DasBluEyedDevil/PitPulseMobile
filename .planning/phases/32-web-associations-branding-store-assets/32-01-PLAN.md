# Phase 32: Web Associations, Branding, and Store Assets

## Scope

Repair release-dependent association files, public page assets, store visuals, mobile asset declarations, and formatting baselines.

## Acceptance criteria

- Association files use verified identities/fingerprints and public lifecycle pages build without missing assets.
- Store graphics accurately depict the release candidate and only runtime assets ship in Flutter bundles.
- Formatter gates pass without mutating source.

## Evidence boundaries

Static association correctness is not device verification, and local screenshot review is not proof of remote listing state.

## Deployment and rollback

Publish web assets atomically with cache-aware verification. Roll back static deploys to the prior immutable release; retain canonical store artwork provenance.
