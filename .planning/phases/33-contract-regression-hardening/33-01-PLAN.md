# Phase 33: Contract and Regression Hardening

## Scope

Turn integration, coverage, HTTP, realtime, push, deep-link, queue, and mobile journey gaps into executable regression gates.

## Finding-to-test traceability

| Finding                      | Change                                               | Required evidence                                        |
| ---------------------------- | ---------------------------------------------------- | -------------------------------------------------------- |
| OB-BE-006                    | Repair integration suite lifecycle/schema assertions | PostgreSQL/Redis CI run closes pools without force exit. |
| MOB-OB-011                   | Raise critical mobile coverage                       | Fresh coverage thresholds and journey-family tests.      |
| Cross-cutting audit matrices | Convert documented contracts to tests                | Producer/consumer and HTTP classification results.       |

## Acceptance criteria

- CI provisions disposable PostgreSQL/Redis, runs migrations, integration tests, and reviewed coverage thresholds.
- Backend and mobile tests cover success, invalid, offline, timeout, retry, and lifecycle behavior for all beta-critical journeys.
- Route and asynchronous contracts have mechanical assertions.

## Evidence boundaries

Coverage is a regression signal, not proof of device, provider, or production behavior.

## Local implementation evidence (2026-07-27)

### Coverage gates

- Backend `npm run test:coverage` now passes with 79 suites passed and one
  skipped, 1,066 tests passed and 19 skipped. Fresh coverage is 65.67%
  statements, 57.29% branches, 65.83% functions, and 65.95% lines against the
  versioned 60/50/50/60 thresholds.
- Mobile `flutter test --coverage` now passes all 307 tests and the fail-closed
  validator. Generated Dart is excluded; every executable hand-written source
  file is present in LCOV. Global coverage is 5,535/12,949 lines, or 42.74%,
  against the 40% target.
- Current critical mobile group results all pass their 70% targets: auth
  79.23%, check-in/photo 70.03%, feed/realtime/push 82.05%, account lifecycle
  75.61%, sharing 78.97%, and subscription 71.14%.
- CI runs fresh coverage before the mobile validator. No hand-written source
  exclusions, threshold reductions, or synthetic coverage were added.
- The first meaningful backend tranche added 64 focused feed, sharing,
  notification, FCM, check-in creation, and photo tests. The full suite passed
  with 688 tests and coverage rose to 41.27% statements, 34.81% branches,
  42.33% functions, and 41.35% lines. The global gate remains red.
- The first mobile tranche added 23 repository/provider/widget tests. The full
  Android/iOS Dart suite passed with 211 tests; global coverage rose to 18.42%,
  check-in/photo to 6.98%, and subscription to 27.64%. Sharing rose from 0% to
  79.37% and is the first critical group to clear its 70% requirement.
- The second backend tranche expanded route, service, worker, provider, cache,
  moderation, audit, provider-adapter, event-sync, badge, discovery, wishlist,
  Wrapped, and push behavior coverage. It closed the global backend gate without
  lowering a threshold or excluding production source.
- The second mobile tranche added 24 check-in provider and widget tests. It
  raised check-in/photo to 70.03% and exposed three runtime defects: repository
  failures falsely reported as successful commands, a deactivated Riverpod
  reference read during check-in-detail disposal, and provider state/reference
  reads during event-room cleanup. The focused fixes retain the authenticated
  session and cleanly leave WebSocket rooms.
- The coverage validator now resolves explicit LCOV paths relative to the
  caller and its no-argument path to `mobile/coverage/lcov.info`. This prevents
  the former CI invocation from reporting a false 0/0 result.
- The final mobile tranches added registration, password recovery, feed,
  realtime, push, account lifecycle, RevenueCat, paywall, browse/filter,
  repository, provider, widget, offline, malformed, timeout, and retry
  coverage. They also exposed and fixed feed read-marker source selection,
  whitespace-normalized password recovery email validation, and a venue refresh
  guard that previously prevented refresh and filter updates from loading.

### HTTP contract classification

- The audit plan referenced a 160-row HTTP matrix, but no versioned 160-row
  artifact exists in the checkout. The current equivalent is derived from the
  TypeScript AST: 152 router endpoints plus 4 direct `app.get` endpoints.
- `docs/contracts/http-route-contract.json` classifies all 156 active
  endpoints as 137 mobile-used, 15 operational/admin, and 4 public. It also
  records three deliberately removed route families for reviews, legacy shows,
  and unauthenticated static uploads.
- `npm run test:http-contracts --prefix backend` validates every router
  mount, per-group endpoint count, sorted signature hash, direct route, allowed
  classification, and retired-route absence. It derives per-row
  authentication, route/inline Zod evidence, request model, response model,
  handler/status source, and effect owner. The local check passes.

### Runtime lifecycle and asynchronous contracts

- The PostgreSQL integration suite now asserts the final nullable UUID
  `checkins.event_id` plus canonical `events` and `event_lineup` tables. It no
  longer contradicts later event-first test setup by expecting the retired
  `shows` model. CI runs the suite separately with `--detectOpenHandles` after
  ordered bootstrap and migrations against PostgreSQL 16.
- `docs/contracts/async-contracts.json` maps nine beta-critical WebSocket,
  push, email-link, queue, webhook, and sharing contracts to their producers,
  consumers, and executable test evidence. `npm run check:async-contracts`
  passes locally and verifies that all 17 backend WebSocket event values are
  understood by the Android/iOS Dart client.
- All BullMQ producer, queue, scheduler, and worker names now use the typed
  `QueueContracts` source. Exported processors make badge evaluation, image
  moderation, event sync, retention routing, failures, and retry propagation
  executable without Redis. The focused async worker suites pass.
- RevenueCat webhook controller tests cover unconfigured and invalid
  authentication, malformed envelopes, canonical mapping/response, and
  retryable processing failure. Existing service tests retain event
  idempotency and database conflict coverage.
- Mobile WebSocket tests consume representative backend envelopes, route them
  to typed streams, and prove malformed JSON does not poison the next message.

### Remaining Phase 33 gaps

- Backend and Android/iOS mobile coverage gates pass without weakening targets
  or excluding hand-written source. Desktop Flutter targets are explicitly
  outside this mobile-app remediation scope.
- The manifest prevents producer/consumer drift and its linked suites exercise
  representative status, model, side-effect, malformed, timeout, and retry
  paths. It does not replace provider, multi-instance, signed-device, or
  end-to-end staging evidence.
- PostgreSQL/Redis service-container execution remains CI/staging evidence;
  Docker is unavailable in this local Windows environment. Signed-device,
  provider-sandbox, deployment, multi-instance, and soak evidence belongs to
  Phase 34 and remains a release blocker until captured.

## Deployment and rollback

Ship only with green contract gates. Roll back code artifacts, not data migrations; keep compatibility for currently deployed clients.
