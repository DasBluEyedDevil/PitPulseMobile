# Phase 31: Mobile Session and Release Correctness

## Scope

Unify authenticated-session initialization and reconcile iOS commercial/release identity configuration.

## Finding-to-test traceability

| Finding | Change | Required evidence |
| --- | --- | --- |
| MOB-OB-012 | One post-auth session bootstrap | Password, registration, Google, Apple, restoration, logout, and account-switch tests. |
| MOB-OB-003 | Reconcile all remaining iOS identity consumers | Firebase/AASA/RevenueCat/docs consistency plus archive/upload evidence. |
| MOB-OB-004 | Confirm release entitlement behavior | Xcode archive effective-entitlement inspection and production APNs delivery. |

## Acceptance criteria

- Every successful authentication path invokes one observable, retry-safe session bootstrap exactly once.
- A valid login and known entitlement survive transient realtime/subscription synchronization failures.
- Android and iOS identities are documented and consumed consistently.

## Evidence boundaries

Mocks cannot prove Apple/Google login, RevenueCat, APNs, or a signed archive. Those require non-secret sandbox/device evidence in Phase 34.

## Deployment and rollback

Release mobile changes through internal tracks first. Roll back by promoting the previously certified binary; preserve server-side entitlement and account records.
