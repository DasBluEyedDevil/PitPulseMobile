# Phase 31: Mobile Session and Release Correctness

## Scope

Unify authenticated-session initialization and reconcile iOS commercial/release identity configuration.

## Finding-to-test traceability

| Finding | Change | Required evidence |
| --- | --- | --- |
| MOB-OB-012 | One post-auth session bootstrap | Password, registration, Google, Apple, restoration, logout, and account-switch tests. |
| MOB-OB-003 | Reconcile all remaining iOS identity consumers | Firebase/AASA/RevenueCat/docs consistency plus archive/upload evidence. |
| MOB-OB-004 | Confirm release entitlement behavior | Xcode archive effective-entitlement inspection and production APNs delivery. |

## Acceptance criteria

- Every successful authentication path invokes one observable, retry-safe session bootstrap exactly once.
- A valid login and known entitlement survive transient realtime/subscription synchronization failures.
- Android and iOS identities are documented and consumed consistently.

## Evidence boundaries

Mocks cannot prove Apple/Google login, RevenueCat, APNs, or a signed archive. Those require non-secret sandbox/device evidence in Phase 34.

## Deployment and rollback

Release mobile changes through internal tracks first. Roll back by promoting the previously certified binary; preserve server-side entitlement and account records.

## Fix round 1: lifecycle race and cleanup hardening

- Reserve an authenticated-session generation before each login, registration,
  social completion, retry, restoration, or logout operation. Serialize
  lifecycle work and require a current generation after every asynchronous
  integration boundary before publishing user, entitlement, or bootstrap
  status.
- Fence WebSocket connection readiness and Firebase token registration with
  service-local generations so delayed work cannot restore a logged-out or
  superseded account.
- Keep the RevenueCat customer-info listener installed across identity and
  customer-info refresh, remove it explicitly during cleanup, and reconcile
  RevenueCat/server evidence conservatively through one generation-aware
  coordinator.
- Run account-transition and logout cleanup as independent, bounded steps.
  Preserve the prior push token for unregister retries, retry only failed
  logout steps once, record permanent cleanup degradation, and clear auth
  storage after the bounded attempt.
- Invalidate the complete catalog of current-user query and mutation providers
  before publishing a replacement account.
- Verify with real production service/default-integration seams in addition to
  orchestration fakes: delayed WebSocket/push/RevenueCat work, listener
  retention/removal, token unregister/register failures, cleanup isolation and
  retry, entitlement truth tables, provider inventory, and publication
  ordering.
