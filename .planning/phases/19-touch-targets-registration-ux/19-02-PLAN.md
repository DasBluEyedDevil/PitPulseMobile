# Plan 19-02: Registration Form UX

**Phase**: 19 — Touch Targets & Registration UX
**Requirements**: UIUX-11, UIUX-12, UIUX-13, UIUX-14
**Depends on**: Nothing (independent of Plan 19-01)
**Estimated tasks**: 5

## Goal

Improve registration form clarity without changing the single-page layout. First Name and Last Name get "(optional)" labels. Password field gets a strength indicator bar (weak/medium/strong). Email gets real-time format validation and username gets debounced availability checking. Confirm password mismatch shows inline before submit. After this plan, users have full feedback on every field before tapping Register.

## Context

**What exists:**

- `register_screen.dart`: ConsumerStatefulWidget with 6 TextFormFields in a single Column
- Form does NOT set `autovalidateMode` — defaults to `AutovalidateMode.disabled` (validators run only on submit)
- Other auth screens (`login_screen.dart`, `reset_password_screen.dart`, `forgot_password_screen.dart`) all use `AutovalidateMode.onUserInteraction`
- Required fields labeled with `*` suffix: `'Email *'`, `'Username *'`, `'Password *'`, `'Confirm Password *'`
- Optional fields labeled without `*`: `'First Name'`, `'Last Name'` — but no "(optional)" text
- `Validators.password` validates: 8+ chars, lowercase, uppercase, digit, special char — returns first failing rule as error message
- `Validators.email` validates email format with regex
- `Validators.username` validates: 3-30 chars, alphanumeric + dots/hyphens/underscores
- Confirm password has inline validator that checks `value != _passwordController.text`
- Backend endpoint exists: `GET /api/users/check-username/:username` (returns `{available: bool}`)
- No mobile-side method calls this endpoint yet
- No password strength widget exists in the codebase

**What's wrong:**

- First Name / Last Name don't indicate they're optional — users may think they're required
- No password strength feedback despite 5 complex requirements (8+ chars, upper, lower, digit, special)
- `autovalidateMode` is `disabled` — all validation errors appear only after submit, unlike every other auth screen
- No way to check username availability before submitting (currently fails on server with "Username already taken")
- Confirm password mismatch only surfaces after submit attempt

**Approach:**

- Keep the single-page layout exactly as-is — same field order, same Form structure
- Add "(optional)" to name field labels — minimal change, high clarity
- Build a lightweight `_PasswordStrengthIndicator` private widget that reads the password controller's text
- Add `checkUsernameAvailability` method to AuthRepository and wire it via a debounced listener
- Switch Form to `AutovalidateMode.onUserInteraction` to enable inline validation on email and confirm password
- For username availability: use a separate state variable + FocusNode + debounced API call (not the form validator, since async validators aren't natively supported in Flutter Forms)

Add the `_updatePasswordStrength` method:

```dart
void _updatePasswordStrength() {
  final password = _passwordController.text;
  int score = 0;
  if (password.length >= 8) score++;
  if (RegExp(r'[a-z]').hasMatch(password)) score++;
  if (RegExp(r'[A-Z]').hasMatch(password)) score++;
  if (RegExp(r'\d').hasMatch(password)) score++;
  if (RegExp(r'[@$!%*?&]').hasMatch(password)) score++;

  setState(() {
    _passwordStrength = score / 5.0;
    if (score <= 1) {
      _passwordStrengthLabel = 'Weak';
      _passwordStrengthColor = AppTheme.error;
    } else if (score <= 3) {
      _passwordStrengthLabel = 'Medium';
      _passwordStrengthColor = AppTheme.warning;
    } else {
      _passwordStrengthLabel = 'Strong';
      _passwordStrengthColor = AppTheme.success;
    }
  });
}
```

**Step 2b**: Add the strength indicator widget below the password field.

Insert immediately after the password `TextFormField` (after line ~229), before the `SizedBox` spacer:

### Task 3: Add username availability check with debounce (UIUX-13)

**File**: `mobile/lib/src/features/auth/data/auth_repository.dart`

Add a new method to check username availability:

```dart
/// Check username availability
Future<bool> checkUsernameAvailability(String username) async {
  try {
    final response = await _dioClient.get(
      '${ApiConfig.auth}/check-username/$username',
    );
    final data = response.data['data'] as Map<String, dynamic>;
    return data['available'] as bool;
  } catch (e) {
    // On network error, return true (available) to avoid blocking registration.
    // Trade-off: user may proceed with a taken username and receive a server error on submit.
    // Mitigation: the registration endpoint validates uniqueness server-side and returns a clear error.
    return true;
  }
}
```

**File**: `mobile/lib/src/features/auth/presentation/register_screen.dart`

**Step 3a**: Add state variables for username availability:

```dart
String? _usernameAvailabilityMessage;
bool _isCheckingUsername = false;
Timer? _usernameDebounce;
```

Add `dart:async` import for `Timer`.

**Step 3b**: Add a listener on `_usernameController` in `initState()`:

```dart
_usernameController.addListener(_checkUsernameAvailability);
```

**Step 3c**: Add the debounced check method:

```dart
void _checkUsernameAvailability() {
  _usernameDebounce?.cancel();

  final username = _usernameController.text.trim();

  // Don't check if too short or fails basic validation
  if (username.length < 3 || Validators.username(username) != null) {
    setState(() {
      _usernameAvailabilityMessage = null;
      _isCheckingUsername = false;
    });
    return;
  }

  setState(() => _isCheckingUsername = true);

  _usernameDebounce = Timer(const Duration(milliseconds: 500), () async {
    final authRepo = ref.read(authRepositoryProvider);
    final available = await authRepo.checkUsernameAvailability(username);

    if (mounted && _usernameController.text.trim() == username) {
      setState(() {
        _isCheckingUsername = false;
        _usernameAvailabilityMessage = available
            ? null  // No message when available (clean state)
            : 'Username is already taken';
      });
    }
  });
}
```

**Step 3d**: Add cleanup in `dispose()`:

```dart
_usernameDebounce?.cancel();
```

- **Confirm password mismatch** (UIUX-14): The inline validator `value != _passwordController.text` runs as user types confirm password

**Step 4b**: Make confirm password re-validate when password changes.

The confirm password field's validator compares against `_passwordController.text`, but Flutter doesn't automatically re-validate field B when field A changes. Add a listener to force re-validation:

In `initState()`, after the password strength listener:

```dart
_passwordController.addListener(() {
  // Force confirm password re-validation when password changes
  if (_confirmPasswordController.text.isNotEmpty) {
    _formKey.currentState?.validate();
  }
});
```

This ensures that if the user changes the password after already typing confirm password, the mismatch error appears/disappears immediately.

> **Trade-off note**: `_formKey.currentState?.validate()` re-validates the **entire form**, not just the confirm password field. This may trigger error messages on other fields (email, username) that the user is still editing. Flutter does not expose a single-field validate API via `GlobalKey<FormState>`. This is acceptable given `autovalidateMode: AutovalidateMode.onUserInteraction` already shows errors progressively; the extra re-validation only fires after the user has typed in the confirm password field.
