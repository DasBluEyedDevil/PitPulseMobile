# Plan 18-02: Semantic Accessibility Labels

**Phase**: 18 — WCAG Contrast & Accessibility
**Requirements**: UIUX-06, UIUX-07, UIUX-08, UIUX-09, UIUX-10
**Depends on**: Nothing (independent of Plan 18-01)
**Estimated tasks**: 5

## Goal

Add semantic labels to every interactive element that screen readers currently can't describe: social icons, star ratings, search clear button, password toggles, and verified badges. After this plan, TalkBack/VoiceOver users can navigate all interactive elements with meaningful announcements.

## Context

**What exists:**
- `_SocialIcon` widget in band_detail_screen.dart has `InkWell` + `Icon` but zero `semanticLabel` or `Semantics` wrapper
- `RatingBar.builder` in rating_bottom_sheet.dart (two instances) has no `Semantics` wrapper — stars are opaque to screen readers
- Search clear `IconButton` in search_screen.dart has no `tooltip`
- Password toggle `IconButton` in register_screen.dart (2 instances) and login_screen.dart (1 instance) — none have `tooltip` or `semanticLabel`
- Verified badge in band_detail_screen.dart already has `Tooltip(message: 'Verified band')` — good
- Venue "Claimed" badge has `Tooltip(message: 'Verified venue')` — good
- Venue "Verified" badge (the `else if venue.isVerified` branch) has NO Tooltip — inconsistent

**What's missing:**
- Social icons: 4 instances need semanticLabel
- Star rating: 2 RatingBar.builder instances need Semantics wrapper
- Search clear: 1 IconButton needs tooltip
- Password toggles: 3 IconButton instances need tooltip
- Verified badges: 1 venue badge branch needs Tooltip wrapper

## Tasks

### Task 1: Add semanticLabel to _SocialIcon instances (UIUX-06)

**File**: `mobile/lib/src/features/bands/presentation/band_detail_screen.dart`

Modify the `_SocialIcon` widget to accept a `semanticLabel` parameter and apply it to the `InkWell` via a `Semantics` wrapper:

```dart
class _SocialIcon extends StatelessWidget {
  final IconData icon;
  final Color color;
  final VoidCallback onTap;
  final String semanticLabel;  // ADD

  const _SocialIcon({
    required this.icon,
    required this.color,
    required this.onTap,
    required this.semanticLabel,  // ADD
  });

  @override
  Widget build(BuildContext context) {
    return Padding(
      padding: const EdgeInsets.symmetric(horizontal: 8),
      child: Semantics(
        label: semanticLabel,
        button: true,
        child: InkWell(
          onTap: onTap,
          borderRadius: BorderRadius.circular(24),
          child: Container(
            width: 48,
            height: 48,
            decoration: BoxDecoration(
              color: color.withValues(alpha: 0.3),
              shape: BoxShape.circle,
            ),
            child: Icon(icon, color: color, size: 24),
          ),
        ),
      ),
    );
  }
}
```

### Task 2: Add screen reader description to star rating (UIUX-07)

**File**: `mobile/lib/src/features/checkins/presentation/rating_bottom_sheet.dart`

Wrap each `RatingBar.builder` in a `Semantics` widget that announces the current rating value. There are two instances:

**Band rating (line ~319):**
```dart
Semantics(
  label: 'Band rating: ${currentRating > 0 ? '${currentRating} out of 5 stars' : 'not yet rated'}',
  liveRegion: true,
  child: RatingBar.builder(
    // ... existing code unchanged
  ),
),
```

**Venue rating (line ~390):**
```dart
Semantics(
  label: 'Venue rating: ${_venueRating > 0 ? '${_venueRating} out of 5 stars' : 'not yet rated'}',
  liveRegion: true,
  child: RatingBar.builder(
    // ... existing code unchanged
  ),
),
```

The `liveRegion: true` flag is essential — without it, a plain `Semantics` widget only announces the initial value. With `liveRegion: true`, TalkBack/VoiceOver will re-announce the label each time the rating changes (on rebuild), giving screen reader users real-time feedback on their selection.

### Task 3: Add tooltip to search clear button (UIUX-08)

**File**: `mobile/lib/src/features/search/presentation/search_screen.dart`

**Line ~65** — add `tooltip` to the clear IconButton:
```dart
// Before:
IconButton(
  icon: const Icon(Icons.clear),
  onPressed: () { ... },
),
// After:
IconButton(
  icon: const Icon(Icons.clear),
  tooltip: 'Clear search',
  onPressed: () { ... },
),
```

Flutter's `IconButton.tooltip` automatically creates a `Semantics` node, so this is the idiomatic approach.

### Task 5: Add Tooltip to venue "Verified" badge (UIUX-10)

**File**: `mobile/lib/src/features/venues/presentation/venue_detail_screen.dart`

The "Claimed" badge branch (line ~138) already has `Tooltip(message: 'Verified venue')`. The "Verified" badge branch (line ~170) does not. Wrap it:

```dart
// Before (line ~170):
else if (venue.isVerified)
  Container(
    padding: const EdgeInsets.symmetric(horizontal: 8, vertical: 4),
    // ...
    child: const Row(
      mainAxisSize: MainAxisSize.min,
      children: [ ... ],
    ),
  ),

// After:
else if (venue.isVerified)
  Tooltip(
    message: 'Verified venue',
    child: Container(
      padding: const EdgeInsets.symmetric(horizontal: 8, vertical: 4),
      // ... existing Container decoration unchanged
      child: Row(          // NOTE: remove 'const' from Row — Tooltip wrapper is not const-compatible
        mainAxisSize: MainAxisSize.min,
        children: [ ... ],  // keep existing children unchanged
      ),
    ),
  ),
```

**Important**: The existing `const Row(...)` must drop its `const` keyword because `Tooltip` is not a const constructor. If `const` is preserved the analyzer will error. The inner `children` list elements can retain their individual `const` annotations.

Note: band_detail_screen.dart verified badge already has `Tooltip(message: 'Verified band')` — no change needed there.
