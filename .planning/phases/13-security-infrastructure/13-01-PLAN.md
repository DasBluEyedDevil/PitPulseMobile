**2a. Migration 039 — Replace plaintext sentinels with bcrypt hashes (backend/migrations/039_replace-social-auth-sentinel.ts)**

Create migration using the node-pg-migrate pattern (same as other migrations in this project).

In the `up` function:
```sql
-- Replace all plaintext '$SOCIAL_AUTH$' values with bcrypt hash of random value
-- Each row gets its own unique random hash so they can't be correlated
DO $$
DECLARE
  r RECORD;
BEGIN
  FOR r IN SELECT id FROM users WHERE password_hash = '$SOCIAL_AUTH$'
  LOOP
    UPDATE users SET password_hash = crypt(gen_random_uuid()::text, gen_salt('bf', 10))
    WHERE id = r.id;
  END LOOP;
END $$;
```

**IMPORTANT**: This requires the `pgcrypto` extension. Add `CREATE EXTENSION IF NOT EXISTS pgcrypto;` before the DO block.

Alternatively, if pgcrypto is not available on Railway PostgreSQL, use a simpler approach — generate a single bcrypt hash in the migration's TypeScript code using bcryptjs, and update all rows with it:

```typescript
import bcrypt from 'bcryptjs';
import crypto from 'crypto';

export async function up(pgm: any): Promise<void> {
  // Generate a random password and hash it with bcrypt
  const randomPassword = crypto.randomBytes(32).toString('hex');
  const hashedPlaceholder = await bcrypt.hash(randomPassword, 10);

  // Replace all plaintext sentinel values
  pgm.sql(`
    UPDATE users
    SET password_hash = '${hashedPlaceholder}'
    WHERE password_hash = '$SOCIAL_AUTH$'
  `);
}

export async function down(pgm: any): Promise<void> {
  // Cannot reliably reverse this — the random password is lost
  // This is intentional: we don't want to restore the plaintext sentinel
}
```

Use the TypeScript/bcryptjs approach (second option) — it's portable and doesn't depend on pgcrypto.
