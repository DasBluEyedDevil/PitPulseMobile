# Plan 20-02: Profile Section Collapsing + Rating Sheet UX Clarity

**Phase**: 20 — UX Restructuring
**Requirements**: UIUX-22, UIUX-23, UIUX-24, UIUX-25, UIUX-26
**Depends on**: Nothing (independent of other Phase 20 plans)
**Estimated tasks**: 6

## Goal

The profile screen reduces initial scroll depth from 9 sections to ~5 visible by collapsing secondary sections (Wrapped, Level Progress, Top Genres, Favorite Bands, Favorite Venues) behind a "See More" expander. The "View All" button on Recent Activity navigates to a full activity list screen. The rating bottom sheet shows helper text when submit is disabled and adds a checkmark indicator on band/venue tabs that have been rated.

## Context

**What exists:**
- `mobile/lib/src/features/profile/presentation/profile_screen.dart` lines ~41-166: 9 content sections in `CustomScrollView` slivers — all rendered simultaneously with no collapsing
- `profile_screen.dart` lines ~150-155: `_SectionHeader('Recent Activity', trailing: 'View All')` with `onTrailingTap` not provided — defaults to `debugPrint` fallback (line ~723-726)
- `mobile/lib/src/features/checkins/presentation/rating_bottom_sheet.dart` lines ~186-188: Submit button disabled when `!_hasAnyRatings` — no explanation text for user
- `rating_bottom_sheet.dart` lines ~161-165: Tab labels are plain `Tab(text: 'Rate Bands')` and `Tab(text: 'Rate Venue')` — no visual indicator of which tabs have been rated

**What's wrong:**
- 9 sections on initial load creates cognitive overload — user must scroll extensively to find specific content
- "View All" on Recent Activity is a dead button that only fires `debugPrint` — broken affordance
- Rating sheet gives no guidance when submit is disabled — user doesn't understand why they can't submit
- No rated/unrated tab indicator — user switching between band and venue tabs can't tell at a glance which have been filled in

### Task 2: Wire "View All" on Recent Activity to activity history screen (UIUX-23)

**File**: `mobile/lib/src/features/profile/presentation/profile_screen.dart`

Provide `onTrailingTap` callback that navigates to the Friends feed tab (index 1 on the feed screen) as a pragmatic destination for "all activity" — the user's full activity is their friends feed + discover feed. This avoids creating a new screen while providing a meaningful destination.

**Lines ~150-155** — add onTrailingTap:
```dart
// Before:
                    const SliverToBoxAdapter(
                      child: _SectionHeader(
                        title: 'Recent Activity',
                        trailing: 'View All',
                      ),
                    ),

// After:
                    SliverToBoxAdapter(
                      child: _SectionHeader(
                        title: 'Recent Activity',
                        trailing: 'View All',
                        onTrailingTap: () {
                          HapticFeedbackUtil.selectionClick();
                          context.go('/feed');
                        },
                      ),
                    ),
```

Note: must drop `const` keyword since `onTrailingTap` closure captures `context`. The `/feed` route navigates to the feed screen where the user can see all activity.
