# 11.2-01 Summary: Mobile Review Response UI

## What was done

### Backend (ReviewService.ts)

- Added `r.owner_response, r.owner_response_at` to SELECT clause in both `getReviewById` (~line 102) and `searchReviews` (~line 269) queries
- Mapper already handled these fields -- no change needed there

### Mobile Review Model (review.dart)

- Renamed `text` field to `content` to match backend JSON key (was a pre-existing mismatch)
- Changed `content` from `required String` to `String?` to match backend optionality
- Added `String? ownerResponse` and `String? ownerResponseAt` fields
- Regenerated freezed/json_serializable files via build_runner

### ClaimRepository (claim_repository.dart)

- Added Review model import

### Claim Providers (claim_providers.dart)

- Added `venueReviewsProvider` -- FutureProvider.autoDispose.family for venue reviews
- Added Review model import

### Owner Response Bottom Sheet (NEW: owner_response_bottom_sheet.dart)

- ConsumerStatefulWidget following ReportBottomSheet pattern
- TextEditingController, _isSubmitting state, keyboard-aware padding
- Submits via ClaimRepository.respondToReview, invalidates venueReviewsProvider on success
- Green SnackBar on success, error SnackBar on failure
- Convenience function `showOwnerResponseBottomSheet(context, reviewId, venueId)`

### Venue Detail Screen (venue_detail_screen.dart)

- Converted `_VenueContent` from StatelessWidget to ConsumerWidget
- Added `_VenueReviewsSection` between Insights and Recent Check-ins (only for claimed venues)
- Section watches `venueReviewsProvider(venueId)` and `authStateProvider` for ownership detection
- Added `_ReviewCard` with: user avatar, username, rating stars, relative time, content, owner response display (with left border accent), and Respond button (owner-only, no existing response)
- Added `_timeAgo` helper for relative date formatting
