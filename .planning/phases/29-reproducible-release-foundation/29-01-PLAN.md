# Phase 29: Reproducible Release Foundation

## Scope

Freeze the remediation baseline and make release inputs/toolchains deterministic for Android, iOS, backend, and the release-dependent web build. No secret, signing key, store upload, or signed-device claim is in scope.

## Acceptance criteria

- The phase snapshot records the immutable baseline, remote, toolchain, lock hashes, redacted credential flags, identities, and deployment targets.
- Android release tasks require all five declared external inputs; they never select debug signing.
- iOS Fastlane targets `com.9thlevelsoftware.soundcheck`; Profile/Release request production APNs.
- CI contains non-mutating format, fresh coverage, dependency audit, licenses, code-generation drift, Android preflight, backend service, and web-build gates.

## Evidence boundaries

Passing static/fixture checks does not close signed artifact, store, APNs, association, deployment, or device evidence. Mark these findings verified only after independent reproduction with retained non-secret logs.

## Deployment and rollback

Deploy configuration only after injecting release inputs through the CI/deployment secret store. Roll back a configuration change by reverting the release-foundation commit; never replace a published signing identity or delete a deployed artifact to compensate.
