<objective>
Remove the legacy `createCheckin(bandId + venueId)` path and all dual-write logic from the SoundCheck check-in stack, leaving only the event-first `createEventCheckin()` flow.

Purpose: The legacy path was kept during the expand-contract migration from v1.0. All mobile usage now goes through the event-first flow. The legacy code adds complexity and maintenance burden.
Output: CheckinCreatorService contains only `createEventCheckin()`. `npm test` passes.
</objective>

**Step 2: CheckinCreatorService.ts — Remove legacy method**
- Delete the entire `createCheckin()` method (approximately lines 231-360)
- This removes:
  - The dual-write INSERT that populates both old columns (band_id, venue_id, rating) and new columns (event_id, venue_rating)
  - The `findOrCreateEvent()` call
  - The `checkin_band_ratings` write from the legacy path
- KEEP all private helper methods (verifyLocation, haversineDistance, isWithinTimeWindow, addVibeTagsToCheckin, invalidateFeedCachesForCheckin, publishCheckinAndNotify)
- KEEP `createEventCheckin()` and `deleteCheckin()` untouched
- KEEP any imports that are still used by the remaining methods

**Step 3: CheckinService.ts — Remove facade method**
- Delete the `createCheckin()` method (approximately lines 99-101) that delegated to `creatorService.createCheckin()`
- KEEP `createEventCheckin()` facade method
- KEEP all other facade methods

**Step 4: CheckinController.ts — Simplify to event-first only**
- In the `createCheckin()` handler, remove the legacy path detection logic
- The handler should now:
  1. Extract `eventId` from request body
  2. If `eventId` is missing, return 400 with `{ success: false, error: 'eventId is required' }`
  3. Call `checkinService.createEventCheckin()` with the event-first data
  4. Return the check-in response
- Remove any references to `bandId`, `venueId` as standalone required fields
- Keep the overall response format unchanged
- Keep audit logging (but update to reflect event-first only)

**IMPORTANT**: Do NOT modify:
- CheckinQueryService.ts (reads from existing data)
- CheckinRatingService.ts (handles per-band rating updates)
- checkinRoutes.ts (same endpoint, no change needed)
- Any migration files
